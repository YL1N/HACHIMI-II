# EEDI 1000条实验简报

## 1. 这次实验怎么做的

这次实验使用的是 EEDI 官方测试集里的 `1000` 条 turn-level 样本，输出目录为：

- [official_test_1000_updated_20260429](D:/Study/sii/MathStudent/eedi/outputs/official_test_1000_updated_20260429)

实验流程分两步：

1. 先做生成  
   给定当前轮之前可见的对话历史、题目文本和学科信息，按我们现在的 EEDI 主方法链生成“当前这一轮学生会怎么说”。

2. 再做离线评测  
   生成完成后，再把模型输出和真实学生回复放到 detached eval 里做四类评测。评测和生成分开，避免把评测信息带回生成链路。

这次运行的主要设置是：

- 目标样本数：`1000`
- 生成并发：`32`
- 生成超时：`180s`
- 文本相似度里的 embedding：`Qwen3-Embedding-8B`

需要注意两点：

- 生成阶段最后是 `1000/1000` 全部跑完。
- detached eval 最终统计到 `956` 条，不是因为生成缺失，而是因为后处理评测时只保留了成功进入该评测流程的记录。

## 2. 我们现在评什么

### correctness

看的是：模型这一轮判断学生“答对了还是答错了”，是否和真实学生一致。

更具体地说：

- 如果真实学生这轮是对的，模型也生成成对的，算匹配。
- 如果真实学生这轮是错的，模型也生成成错的，算匹配。

它评的是“对错方向是否对上”，不要求错得一模一样。

这次结果：

- `correctness = 0.6679`
- 参与该指标统计的样本数：`524`

### same_error

看的是：当真实学生和模型都处于“答错”状态时，模型犯的错是不是和真实学生属于同一种错误。

这是我们现在比官方 `errors` 更贴近目标的版本。它不是看表面像不像，而是看错误在理论分类上是否一致。

这次核心结果：

- `same_error = 0.3333`

也就是在“双方都错，而且都能编码成明确数学错误”的那部分样本里，大约三分之一能对到同一种错。

### cosine similarity

看的是：模型回复和真实学生回复在 embedding 空间里的向量相似度。

- 分数越高，说明两句话整体语义越接近。
- 它更偏“语义接近”，不直接判断对错，也不判断是不是同一种数学错误。

这次结果：

- `cosine = 0.1731`

### semantic similarity

看的是：模型回复和真实学生回复在文本层面的语义相近程度。当前这里用的是 `ROUGE-L`。

- 分数越高，说明两边在关键词和表达结构上更接近。
- 它仍然不是“是否犯了一样的数学错误”的直接指标。

这次结果：

- `semantic similarity = 0.1706`

## 3. 错误相关指标的补充解释

除了 `same_error` 之外，这次 detached eval 还把“同错”拆成了三个更细的维度：

- `same_knowledge = 0.7949`  
  表示双方错误所属的知识类型是否一致。

- `same_locus = 0.5897`  
  表示双方主要错在解题流程的哪个环节是否一致。

- `same_mechanism = 0.5897`  
  表示双方出错的机制是否一致。

另外还有一个很重要的量：

- `error_realization = 0.3514`

它表示：当真实学生确实犯了一个可编码的数学错误时，模型有多大比例也真的生成出了一个可编码的具体错误，而不是生成成正确、含糊困惑、或者不可归类的错。

## 4. 这次实验的简短结论

这次 `1000` 条实验说明：

- 我们的方法已经能比较稳定地对上学生这一轮“总体是对还是错”，`correctness` 到了 `0.6679`。
- 但在“学生具体犯的是哪一种错”这件事上，还明显更难，`same_error` 只有 `0.3333`。
- 从拆分指标看，我们对“错的大类”判断还可以，但对“具体错在什么环节、通过什么机制错出来”还不够稳。
