# XES 学生模拟项目当前实现汇报

## 1. 项目当前在做什么

当前这个项目实现的，不是一个简单的“大模型扮演学生答题”流程。

它实现的是一个 **受控的学生作答模拟系统**：

- 输入是一组学生画像和一张数学卷子；
- 输出是一批模拟学生对这张卷子的作答结果；
- 中间不是直接让模型自由回答；
- 而是先经过学生建模、题目建模、状态判断和约束执行，再生成答案。

当前系统的目标有三项：

1. **总体正确率接近真实学生**
2. **高、中、低、差四档学生有区分度**
3. **题目级表现尽量和真实学生一致**

这三项目标中，第三项最关键，因为它决定系统是否真的知道“哪些题更难，哪些题更容易”，而不只是大致知道学生总分。

---

## 2. 当前系统的总体结构

当前实现可以分成三层：

1. **离线准备层**
2. **在线模拟层**
3. **离线评估层**

整体主链路是：

`学生画像 -> 学生模型 -> 题目需求画像 -> 学生-题目交互判断 -> 单题作答状态 -> 约束包 -> 答案生成 -> 离线评估`

这条链的含义是：

- 先把学生和题目的边界建起来；
- 再判断“这名学生遇到这道题时会怎么样”；
- 最后才允许模型作答。

---

## 3. 离线准备层当前实现了什么

离线准备层当前实现了三件事：

### 3.1 题目池筛选

当前系统不会直接从全部 XES 题目里随机抽题。

进入题目池的题，先经过真实学生作答数据筛选，主要控制：

- 作答人数是否足够
- 不同学生层次是否有覆盖
- 作答样本是否过度偏斜

这一步的作用，是尽量保证题目统计更稳，避免因为作答人群不同而把题目难度看歪。

### 3.2 组卷

当前试卷不是随意拼接出来的，而是按原则化组卷生成的。

当前组卷主要控制：

- 内容覆盖
- 题型分布
- 难度结构
- 平行卷可比性

系统当前已经把 Rasch 难度参数 `b_hat` 接入组卷链路，用于卷内难度控制。

### 3.3 用真实 support set 增强学生画像

当前项目使用的 Hachimi 学生画像本身是合成的，没有真实作答记录。

因此，系统当前额外做了一层 support-set anchoring。

也就是：

- 先在 XES 真实学生中找到和某个画像档位接近的学生；
- 再把这些真实学生在非评测题上的表现，转成画像的能力锚点。

当前已经实现两类锚点：

#### 第一类：粗粒度数学锚点

这类锚点描述的是：

- support 题量
- support 正确率
- easy / medium / hard 三档题上的表现
- 在同档学生中的相对位置

它回答的是：

> 这个画像在真实学生群体里大概处于什么位置。

#### 第二类：结构化数学任务能力锚点

这类锚点描述的是：

- 计算流畅性
- 应用题迁移
- 多步稳定性
- 几何直觉
- 规律识别
- 选择题排除
- 填空精度
- 难题坚持性
- 猜测倾向

这些字段已经写回 persona 文件，并优先进入学生建模。

这一步的意义是：

> 当前画像不再只是“总体强弱描述”，而是带有任务相关能力边界。

## 4. 在线模拟层当前实现了什么

在线模拟层是当前系统的核心。

它由六个连续对象组成。

### 4.1 学生模型

系统当前先把画像转成 `StudentModel`。

这个对象里目前包含两部分信息。

#### 第一部分：稳定学生特征

包括：

- 年级
- 学业水平
- 优势学科 / 薄弱学科
- 自我效能感分析
- 自我调节脆弱点
- 控制—价值分析
- 参与倾向
- 回答直接性

这些字段的作用是稳定学生的作答风格。

#### 第二部分：数学任务能力画像

系统当前已经把 `math_task_capability_profile` 接到学生模型里。

这部分优先来自 support-set 的结构化能力锚点，而不是让大模型自由脑补。

这意味着：

- 学生在计算上强还是弱
- 在迁移上强还是弱
- 在多步题上稳不稳
- 在高格式要求题上是否容易出错

这些信息已经是显式输入，而不是隐含猜测。

### 4.2 内部工程信号

学生模型里的长描述不会直接一路传下去。

系统当前会先把它们压缩成一组内部工程信号，例如：

- 自我效能高低
- 自我调节脆弱度
- 控制感
- 价值感
- 回答直接性

这些信号的作用，是让当前链路更稳定地消费学生特征。

### 4.3 题目需求画像

系统当前不会让模型只看题干。

每道题会先被转成 `ProblemRequirementProfile`，目前主要包括：

- 前置知识要求
- 操作复杂度
- 抽象程度
- 是否需要多知识点整合
- 是否需要表征转换
- 作答格式要求
- 可猜性

这一步的作用，是把“题目文字”转成“题目要求”。

### 4.4 学生—题目交互判断

在学生模型和题目需求画像之后，系统当前会进入 `StudentItemInteractionDecision`。

这一层会综合判断：

- 这道题对这名学生来说是否可达
- 预计正确率落在哪个区间
- 更可能是做对、接近对、还是做错
- 更可能出现什么类型的失误

这一层是当前系统里最关键的中间层之一，因为它第一次显式回答：

> 这道题对这个学生来说，难在哪里。

### 4.5 单题作答状态

系统当前不会从交互判断直接跳到答案。

中间还会先推断 `ItemResponseState`。

这个状态对象当前会描述：

- 学生对前置知识是否熟悉
- 当前题目上属于 mastered / partial / guessable / unreachable 哪一类
- 当前允许的解释深度
- 当前的承诺程度
- 当前的回答风格提示

它的作用不是给答案，而是定义：

> 在这道题上，这个学生当前能做到什么程度。

### 4.6 约束包

系统当前会把单题状态再编译成 `ConstraintBundle`。

当前约束主要包括：

- 是否必须给出明确答案
- 是否允许完整解释
- 最多几句
- 最多几步内部推理
- 是否禁止表现出完全掌握
- 更偏好的错误路径
- 风格约束
- 允许的确定性强度

这一步的作用，是把“状态判断”变成“可执行边界”。

### 4.7 答案生成

当前系统最后才进入答案生成。

目前已经实现两种方式：

1. `direct`
2. `state_step`

当前主线使用的是带状态和约束的生成方式。

也就是说，模型不是直接自由答题，而是在：

- 学生模型
- 题目需求
- 交互判断
- 单题状态
- 约束包

这些条件都准备好之后，才生成答案。

生成之后，系统还会做：

- 违规检查
- 必要时重试

确保最终输出不明显越界。

## 5. 离线评估层当前实现了什么

当前系统的离线评估已经实现三类指标。

### 5.1 总体指标

主要看：

- 总体正确率
- 与真实学生总体正确率的差距

### 5.2 分层指标

系统当前会把模拟学生按高、中、低、差四档统计，并与真实学生四档结果比较。

主要看：

- 四档内部是否拉开
- 每一档与真实学生的整体差距
- 各档题目级表现差距

### 5.3 题目级指标

当前已经实现两条不同的题目级评估线。

#### 第一条：和真实学生正确率的相关

即比较：

- 模拟学生在每道题上的正确率
- 真实学生在每道题上的正确率

当前系统已经输出：

- Pearson
- Spearman

这条线回答的是：

> 模拟结果整体像不像真实学生群体。

#### 第二条：和 Rasch 难度参数的相关

当前系统也已经接入：

- 题目 Rasch `b_hat`

并新增输出：

- `模拟正确率 vs Rasch b_hat` 的 Pearson
- `模拟正确率 vs Rasch b_hat` 的 Spearman

这里理论上应当出现负相关，因为：

- `b_hat` 越大，题越难
- 模拟正确率应该越低

这条线回答的是：

> 系统是否真的感知到了题目本身的难度。

### 5.4 结构性诊断指标

当前系统还会额外统计一些结构性指标，例如：

- 严格单调题目数
- 四档学生是否共享同一个主导答案

这些指标的作用，是检查系统是否只是“总分分开了”，但题目级行为其实仍然过于同质。

## 6. 当前系统的输入和输出文件

当前主实验入口是：

- `xes/run_experiments.py`

每次运行后，系统会产出：

- `selected_questions.json`
- `selected_personas.json`
- `student_models.jsonl`
- `student_signals.jsonl`
- `problem_profiles.json`
- `predictions.jsonl`
- `metrics.json`

当前这些文件已经分别对应：

- 输入题集
- 输入画像
- 学生建模结果
- 工程信号
- 题目需求画像
- 最终预测结果
- 汇总评估指标

## 8. 当前实现的设计原则

当前系统实现遵守三条原则。

### 8.1 不让模型直接自由扮演学生

学生答题必须先经过：

- 学生建模
- 题目建模
- 交互判断
- 状态层
- 约束层

### 8.2 生成链路和评估链路分离

真实学生数据当前只用于：

- 筛题
- 组卷
- 画像增强
- IRT / Rasch 标定
- 离线评估

不会直接把评测卷真实标签带进答题链路。

### 8.3 重点不在 prompt 修辞，而在环境和边界

当前系统实现的核心不是“再写一句更像学生的提示词”，而是：

- 让学生环境更清楚
- 让题目环境更清楚
- 让学生—题目交互边界更清楚
- 让状态和约束真正参与生成

## 9. 当前实现对应的理论依据

### 课程与测评

- 教育部，《义务教育课程方案和课程标准（2022年版）》  
  `https://www.moe.gov.cn/jyb_xwfb/gzdt_gzdt/s5987/202204/t20220421_620068.html`
- The Standards for Educational and Psychological Testing  
  `https://www.testingstandards.net/open-access-files.html`

这部分支撑：

- 为什么要控制年级和内容边界
- 为什么要先筛题再组卷
- 为什么不能只靠单一正确率解释题目

### 教育心理学

- Zimmerman, *Becoming a Self-Regulated Learner: An Overview*  
  `https://eric.ed.gov/?id=EJ656632`
- Tze, Parker, Sukovieff, *Control-Value Theory of Achievement Emotions and Its Relevance to School Psychology*  
  `https://journals.sagepub.com/doi/full/10.1177/08295735211053962`
- Chi & Wylie, *The ICAP Framework: Linking Cognitive Engagement to Active Learning Outcomes*  
  `https://www.tandfonline.com/doi/abs/10.1080/00461520.2014.965823`

这部分支撑：

- 为什么学生模型不能只写一个总水平
- 为什么要保留自我效能、自我调节、控制—价值和参与方式
- 为什么回答风格和解释深度也应进入模拟

### 工程方法

- OpenAI, *Harness engineering: leveraging Codex in an agent-first world*  
  `https://openai.com/zh-Hans-CN/index/harness-engineering/`

这部分支撑：

- 为什么当前实现重点不在 prompt 文案本身
- 为什么要把系统拆成环境、状态、约束、执行和评估
