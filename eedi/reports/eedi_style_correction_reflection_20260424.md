# EEDI 说话风格纠偏反省
这次需要先明确承认一个方法错误：
我之前有一段修法，实质上是在看见 EEDI 里很多学生回复较短之后，开始把“更短、更像短答”当成显式优化方向。
这不符合当前项目原则，也不符合你的要求。
问题不在于“短答”这个现象本身，而在于我把一个数据集表面现象，错误地推进成了 generation path 里的规则。
这会把方法从“第三人称状态建模”拉偏到“看过样本后迎合表面分布”。
这属于应该避免的 cheating 风险。

这次我确认并清理了三类残留问题。
第一类，是用具体短语去特殊放行社交短答。
之前代码里有一段 `_looks_like_brief_social_response(...)`，会对 `hi`、`thanks`、`i'm okay`、`can you help` 这类具体英语短语做识别，然后撤销一部分“过成熟”判定。
这本质上是在把观察到的表面学生话术写回规则。
它不具备一般性，也会把方法带向数据集特化。
现在这段已经删除。

第二类，是把“更短”当成默认纠偏方向。
之前一旦触发 `over_mature_response`，重试逻辑会直接加入 `Be shorter and less polished than the previous attempt.`。
这等于默认认为“学生味”主要靠压短获得。
这和我们当前诊断不一致。
我们现在的问题不是不会判断学生该对该错，而是最后落出来的话还像专家。
所以真正该控的是“不要过成熟、不要教程化、不要超出当前状态允许的表达成熟度”，而不是“变短”本身。
现在这里已经改成更中性的约束：
- 去掉超过当前预测成熟度的额外解释结构
- 不要新增教程式、论证式结构
- 仅在真的出现过成熟时才收紧句数和步数

第三类，是不分违规类型统一压句数和步数。
之前只要重试，就会一律把 `max_sentences` 和 `max_step_budget` 各减一。
这会把所有问题都导向更短输出。
这同样是不合理的。
现在改成：
- 只有 `over_mature_response` 才收紧句数和步数
- `over_fast_transition` 只收紧确定性和承诺强度
- `error_path_discontinuity` 只强调错误路径连续性

这次没有动的核心主链是：
`StudentContextProfile -> TutorTurnProfile -> InteractionState -> StateTransitionPrediction -> ConstraintBundle -> DraftStudentTurn`
这条链仍然负责“学生此刻会怎么想、会答对还是答错、会错到哪里”。
这也是当前指标已经证明我们做得较好的部分。

当前保留的新增层，只有末端表层实现层：
`DraftStudentTurn -> SurfaceRealizedTurn`
它现在只允许做一件事：
在不改变数学内容、不改变对错、不改变错误路径、不改变不确定性的前提下，把专家式表达落成更像学生的话。
这层的目标不是“更短”，而是“不要像老师、不要像题解、不要像成熟专家解释”。

这次改动回答三个问题如下。
1. 改了哪个环节
改的是 `eedi/src/generation.py` 里的违规检查和重试逻辑，以及 `eedi/tests_smoke_longchain.py` 里的测试文案偏置。
2. 理论依据是什么
认知轨迹继续由第三人称状态层驱动；末端表层层只做表达实现，不重写认知状态。纠偏依据不是数据集表面分布，而是“表达成熟度必须服从当前状态边界”。
3. 怎么避免作弊
不再根据 EEDI 已见短答样式写规则；不再用具体学生短语做特殊放行；不再把“更短”当成默认优化方向；不把评测偏好送回生成链。
