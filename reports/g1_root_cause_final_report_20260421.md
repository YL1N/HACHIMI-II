# G1 最终归因报告

## 1. 结论先行

- `主因`：第二层问题，也就是当前模型边界与作答稳定性问题
- `次因`：第一层问题，也就是 persona 信号读取不均衡
- `再次因`：第三层问题，也就是完整方法协议在题目级答案分化上仍然不够好

这三个结论不是拍脑袋排的，而是由 `D1/D2/E1/F1` 连起来得到的。

## 2. 归因链条

### 2.1 为什么第二层是主因

- `D1` 已经证明：即使把 persona 和状态推断都拿掉，只喂最简单的强制状态，模型也不能稳定拉开四档
- `guessable ≈ partial`，`unreachable` 仍然有很高正确率，说明低状态本身压不住
- `F1` 进一步说明：状态层其实相对稳定，但最终答案层高波动，`answer_change_rate` 接近一半

合起来看，第二层问题不只是“能力不够”，而是：

- 低状态边界压不住
- 最终作答不够稳定
- 这两点会直接伤害题目级结构

### 2.2 为什么第一层是次因

- `B2` 和 `B3` 已经证明完整 persona 表示有噪声，而且很多细节没有被稳定利用
- `E1` 进一步拆开后发现，persona 不是整体无效，而是选择性有效
- `math_subject_strength` 和 `efficacy` 能显著改状态
- `srl_fragility` 和 `engagement_style` 很难进入状态层

所以第一层不是“完全失效”，而是“读取不均衡”。这会伤害方法效果，但还不足以解释 `D1` 那种在最简单条件下都拉不开边界的问题。

### 2.3 为什么第三层不是主因

- `C1` 说明状态层本身不是摆设，`state_single/state_step` 比 `direct` 更能保住结构指标
- `D2` 又说明完整协议并没有简单把状态差异吃掉；相反，它在整体均值层面还帮忙把四档排开了

但第三层也不是没问题：

- `D2` 的题目级严格递降仍然很低
- 跨状态主流答案相同题数反而更高

所以第三层更像“没有把已有状态差异真正落实到题目级答案分化”，而不是根本主因。

## 3. 最终排序

1. `主因：第二层模型边界与作答稳定性`
2. `次因：第一层 persona 信号读取不均衡`
3. `再次因：第三层方法协议没有把状态差异充分落实到题目级答案分化`

## 4. 可修复项

- 第一层：
  - 继续收缩 persona，只保留能稳定进入状态层的字段
  - 对 `srl_fragility / engagement_style` 这类抽象特质，重新设计更可操作的表达
- 第三层：
  - 重点改 `state -> answer` 这段，而不是继续堆 persona 文本
  - 让状态差异更多体现在题目级答案分化，而不是只体现在整体均值顺序
  - 继续审查哪些协议步骤会放大答案趋同

## 5. 当前模型时代限制

- 即使把问题拆到最简单，当前模型也不能稳定服从细粒度的学生状态边界
- 即使状态判定相对稳定，最终答案仍然有明显随机波动
- 这意味着在当前模型代际下，想要把“真实学生题目级对错模式”做得很稳，会被明显卡住

## 6. 项目判断

下一阶段不该继续把主要精力放在：

- 给 full persona 加更多细节
- 继续手调“更像学生”的 prompt

更应该放在：

- 收缩并重写真正有效的 persona 信号
- 直接针对 `state -> answer` 这一段做更可审计的约束实现
- 承认并记录当前模型边界，不把第二层问题伪装成方法优化空间
